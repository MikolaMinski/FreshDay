# Развёртывание на хостинге с Plesk (hoster.by)

Схема работы после настройки:

```
вы правите код → git push в main
        │
        ▼
GitHub Actions (.github/workflows/hosting.yml) собирает
        ├─ сайт            → ветка hosting      ─┐
        └─ сервис заявок   → ветка hosting-api  ─┤ webhook
                                                 ▼
                          Plesk «Развернуть с помощью Git» сам забирает обновления
```

Plesk не умеет собирать Astro и .NET, поэтому собирает GitHub, а Plesk получает готовые файлы.

Порядок: **часть 1 обязательна** — после неё работают сайт и форма заявки (через PHP → Telegram).
**Часть 2** — сервис заявок на .NET, по желанию; ему нужен свой поддомен (например,
`api.freshday.by`), поэтому делается после подключения настоящего домена.

---

## Часть 1. Сайт и форма заявки

### 1.1. Адрес сайта для сборки

По умолчанию сайт собирается для `https://freshday.by` (адрес задан в `src/config/site.ts`).
Если нужен другой адрес, задайте переменную GitHub → **Settings → Secrets and variables → Actions
→ Variables** → `HOSTING_SITE_URL` (например, `https://vh419.by2040.ihb.by`) и запустите
**Actions → Build for Plesk hosting → Run workflow**. От адреса зависят canonical-ссылки,
sitemap и разметка для поисковиков.

Проверьте, что в **Actions** запуск **Build for Plesk hosting** зелёный и в репозитории есть
ветка `hosting`.

> **Linux или Windows?** Сайт готов к обоим: на Linux (Apache) работает `.htaccess`, на Windows
> (IIS) — `web.config`. Настройки ниже одинаковые; путь к корню домена на Windows выглядит как
> `C:\Inetpub\vhosts\freshday.by`, на Linux — `/var/www/vhosts/freshday.by`.

### 1.2. HTTPS и PHP в Plesk

1. Домен → **Хостинг и DNS → SSL/TLS-сертификаты** → бесплатный **Let's Encrypt** для домена и
   `www`. Это нужно сделать до запуска сайта: `.htaccess` переводит всех посетителей на `https://`.
2. Домен → **Хостинг и DNS → PHP**: версия **8.1 или новее** (лучше самая новая из списка).

### 1.3. Очистить папку сайта

**Диспетчер файлов → httpdocs**: удалите всё, что Plesk положил туда при создании домена
(`index.html`, `css`, `img`, `favicon.ico` и т. п.). Иначе стартовая страница Plesk может
перекрыть сайт.

### 1.4. Подключить репозиторий

Домен → вкладка **Начать** → **Развернуть с помощью Git** (или раздел **Git**):

| Поле                | Значение                                                       |
| ------------------- | -------------------------------------------------------------- |
| Репозиторий         | **Удалённый** — `https://github.com/MikolaMinski/FreshDay.git` |
| Ветка               | `hosting`                                                      |
| Режим развертывания | **Автоматический**                                             |
| Путь развертывания  | `httpdocs`                                                     |

Репозиторий публичный — SSH-ключ и пароль не нужны. После создания нажмите **Извлечь
обновления** (Pull updates) — файлы сайта появятся в `httpdocs`.

### 1.5. Автообновление (webhook)

В настройках репозитория в Plesk (значок шестерёнки у Git) скопируйте **URL веб-хука**.
GitHub → **Settings → Webhooks → Add webhook**:

- **Payload URL** — вставьте URL из Plesk;
- **Content type** — `application/json`;
- **Which events** — _Just the push event_.

Теперь каждый push в `main` через 2–3 минуты сам оказывается на хостинге.

### 1.6. Бот для заявок

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot`, сохраните токен
   `123456789:AAH…`.
2. Создайте группу для заявок, добавьте в неё бота и напишите в группе любое сообщение.
3. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите
   `"chat":{"id":-100…` — это ID группы (с минусом).

### 1.7. Настройки формы

**Диспетчер файлов** → поднимитесь на уровень **выше** `httpdocs` (корень домена, рядом с папками
`httpdocs`, `logs`) → **Создать файл** `freshday-config.php`:

```php
<?php
return [
    'telegram_token'    => '123456789:AAH...',
    'telegram_chat_ids' => [-1001234567890],
    // Необязательно — копия заявки на почту:
    'email_to'   => '',
    'email_from' => '',
];
```

Файл лежит вне папки сайта: браузер его не откроет, а обновления из Git его не затронут.
Там же появится `freshday-leads.log` — копия каждой заявки на случай, если Telegram был недоступен.

### 1.8. Проверка

- Откройте сайт, отправьте заявку с любой страницы — она должна прийти в группу.
- Страница `https://<домен>/несуществующая/` показывает фирменную страницу 404.

## Часть 2. Сервис заявок на .NET (по желанию)

PHP-обработчик из части 1 уже доставляет заявки. Сервис из `server/` умеет больше: повторяет
отправку при сбоях Telegram, сам подсказывает ID группы, отвечает на `/chatid`, хранит архив в
JSON. Его стоит поднимать, когда у сайта есть свой домен.

> **Проверьте версию .NET.** Сервис написан на **.NET 10**. При создании «Сайта .NET» Plesk
> показывает список доступных версий. Если 10 в нём нет — напишите, какие есть: проект можно
> перевести на ту версию, что установлена у хостера.

1. **Добавить субдомен** `api` (получится `api.freshday.by`) → на вкладке **Начать** выберите
   **Сайт .NET**, версия **10.x**.
2. Выпустите для субдомена сертификат **Let's Encrypt** (как в 1.2).
3. **Git** для субдомена: репозиторий тот же, ветка **`hosting-api`**, режим автоматический,
   путь — корневая папка субдомена (её показывает Plesk, обычно `api.freshday.by`). Добавьте
   второй webhook в GitHub, как в 1.5.
4. Настройки **.NET** субдомена:
   - **Файл запуска** (Startup file, только Linux): `FreshDay.LeadBot.dll`. На Windows файл
     запуска не нужен: в ветке `hosting-api` уже лежит `web.config` для IIS, который запускает
     сервис сам; переменные окружения задаются в настройках ASP.NET Core домена.
   - **Переменные окружения**:

     | Имя                          | Значение                             |
     | ---------------------------- | ------------------------------------ |
     | `Telegram__BotToken`         | токен бота                           |
     | `Telegram__Chats__0__Id`     | ID группы, например `-1001234567890` |
     | `LeadBot__BehindProxy`       | `true`                               |
     | `LeadBot__SiteUrl`           | `https://freshday.by`                |
     | `LeadBot__AllowedOrigins__0` | `https://freshday.by`                |
     | `LeadBot__AllowedOrigins__1` | `https://www.freshday.by`            |

   Если ID группы ещё неизвестен — оставьте его пустым, запустите сервис и добавьте бота в
   группу: он сам напишет ID.

5. Включите приложение и откройте `https://api.freshday.by/health` — должен быть ответ `{"status":"ok"}`.
6. GitHub → Variables → `HOSTING_LEAD_API_URL` = `https://api.freshday.by/api/lead` → **Run
   workflow**. Форма начнёт отправлять заявки в сервис вместо `lead.php`.

После обновлений из Git нажмите в настройках .NET **Перезапустить** (Restart), если Plesk не
перезапустил приложение сам.

## Если что-то не так

| Признак                                       | Что проверить                                                        |
| --------------------------------------------- | -------------------------------------------------------------------- |
| Видна стартовая страница Plesk                | шаг 1.3, затем **Извлечь обновления** в Git                          |
| «Слишком много переадресаций» / нет HTTPS     | сертификат Let's Encrypt (1.2)                                       |
| Сайт без стилей, ссылки ведут на `/FreshDay/` | `HOSTING_SITE_URL` задан, запуск **Build for Plesk hosting** зелёный |
| Форма: «не удалось отправить»                 | `freshday-config.php` (1.7), версия PHP ≥ 8.1, бот в группе          |
| Изменения не доезжают                         | GitHub → Settings → Webhooks → последняя доставка зелёная            |
| Сервис .NET не стартует                       | логи в **Логи** субдомена; версия .NET 10; файл запуска              |
